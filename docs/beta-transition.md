# MVP Completion And Beta Transition

このドキュメントは、KAZOQ を MVP 完了から β版へ移行するための確定スコープを、実装順と完了条件つきでまとめたものです。

## 1. 現在地

すでに整っている中核は次です。

- アカウント作成、ログイン、家族ルーム作成、招待参加
- `rooms/[familyId]` を正規ルートにした家族ルーム導線
- トップ限定デモと、本利用導線の分離
- メッセージ、報連相、予定、日記、場所共有の基本機能
- 家族ごとの初期カスタマイズと設定変更
- Supabase 連携の基本構成

β版完了までの残りは、主に `情報の整理` と `運用機能の追加` です。

## 2. β版の完了条件

以下が揃ったら、β版へ移行できる状態とみなします。

- 生活連絡の基本導線が迷わず使える
- ホームと各画面の情報量が過不足なく整理されている
- 家族ルームごとに不要機能を外せる
- 地図、通知、公開範囲、タスクの最小構成が使える
- 実運用目線の動作確認と細かい不具合修正が一巡している

## 3. 実装フェーズ

### Phase 1. メッセージ既読

目的:
家族内の「読んだ / まだ見ていない」を最小コストで把握できるようにする。

実装内容:

- `message_reads` を本運用する
- メッセージ一覧表示時に既読を付ける
- メッセージカードで既読人数を見せる
- 必要なら既読メンバー名を軽く確認できるようにする

完了条件:

- メッセージを開くと既読が保存される
- 同じユーザーの重複既読が増えない
- UI 上で既読状態が確認できる

### Phase 2. 報連相テンプレートの簡素化とワークフロー最適化

目的:
報連相を「雑談」ではなく「家庭内オペレーション」として使いやすくする。

実装内容:

- 投稿テンプレートを `ご飯 / 欠食 / 外泊 / お迎え / 帰宅` 中心に絞る
- 入力項目を最小限に整理する
- `確認待ち / 進行中 / 完了` の導線を明確にする
- 返答、完了、再確認のUIを一本化する

完了条件:

- 最小入力で報連相を起票できる
- 家族が次に何をすればよいか分かる
- タイムラインが長くても追いやすい

### Phase 3. 情報量の最終整理

目的:
ホームと各画面を、毎日見る前提でちょうどよい密度に整える。

実装内容:

- ホームのカードと優先順位を見直す
- メニュー、ショートカット、詳細導線を減らしすぎず整理する
- モバイルでの視認性、押しやすさ、一覧性を調整する
- 家族設定でメッセージやカレンダーなどを `不要` にできる状態を完成させる

完了条件:

- ひと目で「今日必要な情報」が分かる
- 使わない機能が前面に出てこない
- スマホでの読み疲れが大きく減っている

### Phase 4. 地図機能の本格化

目的:
見守りと場所共有を、実利用できるレベルまで引き上げる。

実装内容:

- プレースホルダー地図を実地図へ差し替える
- `常時更新` と `手動で場所を送る` の方式を選べるようにする
- 現在地、登録地点、予定の場所をつなげる
- 位置共有の扱いを家族が理解しやすいUIにする

完了条件:

- 地図上で現在地や登録地点が確認できる
- 常時更新か手動共有かを選べる
- 予定との結びつきが見える

### Phase 5. 通知 / 公開範囲 / タスク管理

目的:
β版で実際に使い続けられる運用機能を揃える。

実装内容:

- 通知のON/OFFや優先度を管理できるようにする
- 日記や位置情報の公開範囲を管理できるようにする
- 家事や依頼をタスクとして扱えるようにする
- 報連相とタスクの役割分担を整理する

完了条件:

- 必要な通知だけを受け取れる
- 公開範囲の誤解が起きにくい
- 「やること」を報連相と切り分けて扱える

### Phase 6. 実運用目線の最終QAと不具合取り

目的:
開発者目線ではなく、家庭で毎日使う前提で粗さを潰す。

確認内容:

- 新規登録から家族ルーム開始までの一連動作
- 招待参加と既存ルーム合流
- モバイルでの操作感
- データ0件時の空状態
- 認証切れ、位置情報拒否、入力失敗時の挙動
- 見た目、言葉、押し先の違和感

完了条件:

- 致命的な導線詰まりがない
- エラー時に利用者が迷いにくい
- β版参加者へ渡せる完成度になっている

## 4. 優先順

β版へ最短で到達するおすすめ順は次です。

1. メッセージ既読
2. 報連相テンプレートの簡素化とワークフロー整理
3. 情報量の最終整理
4. 地図機能の本格化
5. 通知 / 公開範囲 / タスク管理
6. 実運用目線の最終QAと細かい不具合取り

## 5. 実装メモ

- `/home` は入口、正規ルートは `/rooms/[familyId]`
- デモ体験はトップ `/` のみで提供
- 家族設定で不要機能を外せる構造を前提に進める
- β版では「高機能」より「迷わず使える」を優先する
